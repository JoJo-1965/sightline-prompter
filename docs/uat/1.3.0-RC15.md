## Short retest after the existing production recording

The earlier 22-section production recording already supplies real-world
evidence and informed the Retake/tracking corrections. RC15 needs a targeted
check of subsequent changes. Allow about five minutes; keep your production
script unchanged. The optional RC15 sample is available under File > Sample
scripts, or use a disposable personal copy.

1. Record 30–60 seconds. Use Next section, Retake, Pause and Go. Pause, edit
   one word, save and resume Voice. Confirm the reading line stays with you.
2. Finish OBS, start a second short recording and finish again. In Recording
   review, check the two output references and export recording-links.json.
   Each take must retain the correct recording identity and reported file.
3. Recompare saved timed words, or import a timed transcript if available.
   Check the timing-quality message and exported evidence. No transcript or
   model setup means this part remains untested; it is not a pass.
4. In Configure MCP, check the generated profile and run Check connection.
   Reconnect a client when convenient to verify the same eight tools. In
   Debug, try a recognised and an unmatched command, inspect the result and
   opened microphone, then Clear the recent command words.

Keep the short recording and log for review if anything stalls or misbehaves.
The existing film remains production evidence; this check covers the newer RC.

## Detailed checks

1. Record two takes, finish OBS, start another recording in OBS and repeat.
   Review the session and recording-links.json: every known file belongs to
   the correct take/recording identity. Test an external stop/restart and a
   split output. An interrupted connection must show uncertainty.
2. In Recording review, import/transcribe recorded words, inspect timing
   quality and recompare saved words. A repeated opening in the second take
   must not fill missing evidence for the first. Export and inspect original
   live-* files, recording-links.json and timing-quality.json. Original log,
   ratings and keepers remain unchanged.
3. Open Connections > MCP, AI, and API > Connection setup and test. Copy JSON
   or the Codex command, check its active profile, retain other client entries,
   Apply and Check connection. Reconnect a client and call sightline_status.
   Expect eight tools. Read-only defaults and disabled grants must still hold.
4. Open Debug > Status and recovery > Microphone, commands and OBS diagnostics.
   Start normal listening, issue a valid command and try an unmatched command.
   Inspect actual input, applied processing, heard phrase and outcome. Check
   an OBS command with recording permission off. Clear removes recent words;
   the panel does not enable persistent tracing or start an extra microphone.
5. Confirm the existing Stream Deck profile, pad/phone functions, script slots,
   saved appearance, Voice edit/resume and compact toolbar still work.

The native fixtures use disposable profiles and mock input/status data. They
do not establish real microphone acoustics, camera lip sync, physical controller
acceptance or cross-platform hardware behaviour. Public v2 naming/publication,
companion Marketplace submission and live JL deployment remain separate.
