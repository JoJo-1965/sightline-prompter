# Feedback queued during 1.3.0 RC11 UAT

12 November 2026. These are reported issues and acceptance requirements for
the next combined candidate, not changes included in the running RC11 build.
Keep the current app, saved settings, script slots and UAT session intact.

## Toolbar utility controls

Status: queued for the next RC.

Joanne reported two forms of the same layout issue:

- On the smaller prompter window, Help and Settings wrap alone onto a second
  row, leaving two orphaned controls and a largely empty toolbar row.
- On a larger window, Help and Settings sit lower than the minimise,
  maximise/restore, fullscreen and Close buttons.

The markup currently gives Help/Settings a normal wrapping flex group, while
the four window controls are absolutely positioned at the top right. Those
different layout rules explain the separation and inconsistent alignment.

### Required result

- Keep Help, Settings and the four window buttons together as one coherent
  utility group at the top right of the first toolbar row.
- Give all six buttons the same vertical alignment, height and spacing.
- Retain the compact script-slot picker on smaller windows and numbered
  buttons on wide windows, including Ctrl+1 through Ctrl+9.
- Let other toolbar functions use coherent additional rows where necessary;
  keep every action visible and accessible.
- Keep session/OBS controls below the complete toolbar, with the existing
  reading-line clearance, auto-hide and keyboard focus behaviour.

### Acceptance for the combined build

Render the actual toolbar at 560, 768, 800, 1024 and 1920 pixels wide, including
the reported narrow and wide states. Check both Voice and Scroll, nine occupied
slots, visible slider values and the OBS/session row. Verify common button
alignment, no orphaned utility controls, clipping or overlap, keyboard access
and auto-hide recovery. Compare the rendered layout as well as element bounds.

Update the cumulative 1.3.0 release notes in the next RC section, affected
screenshots, guide/help and JL preview references with the combined handover.

## Editor Close and Cancel

Status: queued for the same next-RC batch.

The full script editor currently shows Cancel even when the script has no
unsaved changes, including immediately after Save. Joanne requested a dynamic
label so the available exit action is clear.

### Required result

- Show **Close** when there are no unsaved changes; return to the prompter.
- Switch to **Cancel** while there are unsaved edits, retaining the existing
  confirmation before discarding them.
- Return to **Close** only after Save/Save As succeeds, or Undo restores the
  saved text. A failed save or cancelled file dialog must retain the draft and
  the Cancel state.
- Keep Save and Save As available for their existing purposes. Close exits
  the editor rather than closing Sightline.
- Preserve the clear Back to prompter action for read-only sample source and
  its Save a copy route.

### Acceptance for the combined build

Check a clean opened file, a changed file, successful Save, successful Save As,
Undo back to the saved text, a cancelled Save As dialog and failed persistence.
Confirm that cancelling the discard prompt keeps the editor and its draft open;
confirming it returns to the saved script. Include keyboard/screen-reader labels
and the small-window editor toolbar. Update help, screenshots and the next RC's
section of the cumulative release notes with the combined implementation.
