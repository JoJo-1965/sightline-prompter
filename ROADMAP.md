# Sightline Prompter roadmap

What's planned and in which order. Joanne approved every item on 27 October
2026, apart from the one on hold. The [change log in the README](readme.md#change-log)
records what has shipped.

**How it's ordered:** first by **value**, meaning what makes recording to camera better, then by **effort**. Quick wins come first; long,
complex builds come later.

- **Value:** ★★★ changes recording day · ★★ clearly better · ★ nice to have
- **Size:** **S** about a day · **M** a few days · **L** a week or more

| 10  | ✅ **Pacing indicator, with two modes.** **Section mode** (the default, for batch and modular recording with pause points): the timer restarts at each section and stops while paused, and each section shows its target time or words per minute against your actual pace, with an on-track / ahead / behind light (green, amber or red, always with words). A short per-section log appears after each take. **Whole-session mode** (one continuous recording): elapsed against target time, overall on/off track, and target against actual words per minute. ## 1.4: recording workflow

Ideas from 27 October 2026. Voice scrolling already knows which word was said
when, which section was being read and when "Prompter, again" was said; these
items keep that information and put it to work in the edit and in rehearsal.
Ordered by value, then size.

| #   | Item | Value | Size | Notes |
| --- | ---- | ----- | ---- | ----- |
| 23  | ✅ **Take log for the edit:** record each section and take as it happens (start and end times, retakes from "Prompter, again", markers) and export it when you stop, as JSON for an edit pipeline (and CSV), so the edit can pick the last good take of each section and cut false starts automatically | ★★★ | M | Recommended next, ahead of 20, so it pays off on the next module recording. Times line up with the recording by the slate (25) or the take's start |
| 24  | ✅ **"Prompter, keeper" and "Prompter, scrap that":** rate a take as you go; the rating goes into the take log, so the edit uses your verdict rather than just the last take | ★★★ | S | Builds on 23 |
| 25  | ✅ **Slate and sync mark:** at the start of each take, a full-screen slate ("M2 · Section 3 · Take 2") for a second, with a sharp beep and a white flash, giving the edit a sync point and a label in the footage | ★★ | S | Replaces the hand clap, which lands late when clapped straight after pressing record |
| 26  | **Word-level timing, edit marks and captions:** in voice mode, record when each script word was spoken (from the speech engine's own word timings, about a twentieth of a second apart, not from when the screen scrolled) and save it with each take: every word, its start and end, and the sentence and section it belongs to, plus pauses and stumbles (words said twice, skipped or not in the script). Export it with the take log as JSON and CSV, as edit marks (sentence starts, long pauses, fluffs) for cutting, and as SRT or VTT captions in the script's own wording, with nothing sent anywhere; and a "script against what you said" comparison | ★★★ | M | **Part done (28 Oct):** voice mode now records each script word with the time it was said (from sherpa's token timestamps) on every take in the take log JSON, a re-read replacing the first reading. Still to do: end times, sentences, stumbles, edit marks, captions, the CSV and the edit pack. Raised from ★★ on 28 Oct (Joanne asked for word-level timing for editing marks). Export it as an **edit pack** an editing and assembly agent can use whole: the take log, word timings, edit marks and captions in one folder, with a schema and a brief for edit agents (docs/EDIT-PACK.md, like the AI script brief), so an agent can pick takes, cut to sentence boundaries and line up the recording from the slate. Steady scrolling has no word timings (nothing is listening), so this is voice mode, or steady with voice commands on |
| 27  | **Code signing for Windows and Mac:** no more "unknown publisher" warnings | ★★ | S | Moved up from Later. Needs a code-signing certificate and an Apple Developer account (Joanne's decision) |
| 28  | **Rehearsal coach:** after a practice run, pace by section, lines skipped, "um"s and sentences you stumbled on, all on the computer | ★★ | M | Same speech engine as voice scrolling |
| 29  | **Automatic updates:** new versions download and install themselves, so users get fixes without reinstalling | ★★ | M | Moved up from Later. Best done with code signing (27), which Mac updates need |
| 30  | **Script health check in the editor:** reading time per section, and flags on sentences too long for one breath and on tongue-twisters | ★ | S | |
| 31  | **Scripts folder sync:** choose a OneDrive, Dropbox or other folder, and scripts saved there from another computer appear in Sightline | ★ | S | |
| 32  | **Advance slides at cue words:** when you say a slide-cue phrase, press the next-slide key in PowerPoint or Keynote, for live talks and webinars | ★ | M | Builds on the slide-cue highlighting that's already there |
| 33  | **Scratch audio for syncing:** record a plain audio file from the microphone while the prompter runs, stamped to the take log, so an edit pipeline can line up the master recording (Riverside or anything else) by matching the two soundtracks, with no clap or beep needed | ★★ | M | Joanne's idea, 28 Oct. Riverside stays the master recording; this is only a sync reference |
| 34  | **Record a quick take:** webcam and microphone recording inside Sightline, one file per take, named and rated from the take log, for people with no recording software | ★ | L | Joanne's idea, 28 Oct. Not for masters: browser-engine encoding is fine for reference copies but below Riverside's local 4K quality |
| 35  | **Script-controlled listening and prompter commands**, so the scripting agent can direct the prompter: `{listen: off}` before an ad-lib, a demo, Q&A or any part that doesn't need it: the microphone switches off completely (nothing is listened to that doesn't need to be), the prompter holds its place or scrolls steadily, and Space, the clicker or the remote carries on; `{listen: on}` switches the microphone back on and voice following resumes. The rule throughout: the mic is only on when something needs it; and `{prompter: …}` to run any voice command at that point in the script (`{prompter: slower}`, `{prompter: bigger}`, `{prompter: marker}`). Added to the directive spec, the script checker and the AI script prompt, and recorded in the edit pack so the edit knows which parts were off script | ★★ | M | Joanne's idea, 28 Oct. Pairs with 26: the scripting agent writes the directions, the editing agent reads the result |
| 36  | **Recordings library, and agent access to it:** a panel (File > Recordings) listing every recording session: script, date, takes, keepers and length. Open one to see its takes and words; **rename** it, add a note, **delete** it (to the Recycle Bin, with a confirmation), start a new one, and **export** its edit pack as a folder or zip. An AI agent on the same computer can do the same through the token-protected local API: list sessions, fetch a session's edit pack, rename, mark as processed or delete (only if allowed in Settings > Remotes). The edit-pack brief (docs/EDIT-PACK.md, also on the clipboard from Help) tells the agent how to ask for a session, what each file holds and how to process it: line up the recording from the slate, choose the takes, cut at sentence boundaries, assemble in script order | ★★★ | M | Joanne's idea, 28 Oct. | 37  | **Clickable progress bar:** click or drag the progress bar to jump to any point in the script, with a tooltip showing the section and time at that point; section boundaries marked as ticks along the bar. Replaces the scroll bar the script no longer shows, without the risk of grabbing it mid-take (clicks are ignored while scrolling unless paused) | ★★ | S | Joanne's idea, 28 Oct, after the scroll bar was removed |
| 38  | **Check for updates:** a **Check for updates** button on Settings > About, and an optional quiet check when the app starts (on by default, off in Settings), against the latest GitHub release. If there's a newer version, a note says so with a link to the download and what's new; nothing downloads or installs by itself, and nothing else is sent | ★★ | S | Joanne's idea, 28 Oct.
